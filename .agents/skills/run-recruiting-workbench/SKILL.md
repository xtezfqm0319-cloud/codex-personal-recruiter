# 运行招聘工作台

## 目标

让用户只表达招聘目标，不需要识别当前流程阶段、记住 Skill 名称、寻找文件或把一个业务任务拆成多条命令。理解用户真正想解决的问题，调用现有专业 Skills 完成判断和落盘，并把对话压缩成用户可以立即采取行动的结果。

开始前完整阅读 [招聘意图路由与连续执行规范](references/招聘意图路由与连续执行规范.md)，按其中的意图分类、组合路径、连续指代、打断边界和统一输出规则执行。

## 定位与边界

1. 总入口只负责理解、路由、编排、连续推进和统一交付，不重写专业判断标准。
2. 一旦选择专业 Skill，必须完整读取并遵守该 Skill 及其 references，不得用总控摘要替代专业规则。
3. 用户请求已明确对应单一环节时，可直接使用专业 Skill；不要为了经过总入口而增加一次复述。
4. 多环节任务尽量在一轮内完成所有无需用户介入的步骤，不在每个文件动作或 Skill 之间停顿。
5. 权限边界、事实来源、AI 建议与人工结论分层继续以 `AGENTS.md` 为准；总控入口不得降低确认要求。
6. 不向用户展示内部路由、Skill 名称、CLI、索引和移动过程，除非失败、存在异常或用户主动询问。

## 执行流程

### 1. 先确定用户想得到的业务结果

保留用户原话，优先识别：

- 对象：公司、岗位、候选人、批次、某轮面试、历史人才或整个工作台；
- 动作：建立、处理、比较、确认、准备、分析、决定、归档、查找、校准或安排优先级；
- 约束：可投入时间、面试名额、截止日期、希望的输出深度；
- 延续关系：“前两个”“他们”“按刚才的建议”“继续”等是否指向上一轮明确名单或决定。

不要把“看看”“处理一下”“怎么办”机械翻译成固定命令。结合当前主档案和流程阶段判断用户真正需要的下一项业务决策。

### 2. 读取最小必要状态

先读 `AGENTS.md`、`00_公司认知/个人招聘判断偏好.md`，再按用户对象读取：

- 全局请求：岗位清单、活跃候选人、待确认事项和待处理目录；
- 岗位请求：正式 `岗位.md`、岗位比较、批量确认汇总和活跃候选人总览；
- 候选人请求：候选人总览、当前阶段、相关原始材料和最新分析；
- 连续请求：上一轮明确展示的名单、顺序、建议和待用户决定项。

只读取支持本次路由和决定所需的材料。不要因为总控入口被触发就重读全部历史档案。

### 3. 选择最短完整路径

根据目标调用一个或多个专业 Skill：

- 建岗位、讨论 JD：`$create-position`
- 新简历、批量筛选：`$process-resumes`
- 岗位内排序或有限名额选择：`$compare-candidates`
- 写入人工筛选决定：`$confirm-screening`
- 准备下一轮面试：`$prepare-interview`
- 处理面试纪要、判断是否继续：`$analyze-interview`
- 终面或录用讨论准备：`$generate-final-brief`
- 结束流程和归档：`$close-candidate`
- 查找历史人才：`$search-history`
- 复盘岗位定义和筛选误判：`$calibrate-position`
- 学习用户明确反馈：`$learn-recruiting-preferences`
- 今天先做什么、跨岗位注意力安排：`$daily-recruiting-brief`

不要重复调用已经包含在专业流程内的步骤。例如 `$process-resumes` 已要求完成岗位内比较时，不再为形式完整重复生成第二套比较。

### 4. 连续完成无需用户介入的工作

可以直接执行的整理、分析、报告、索引和明确归档动作一并完成。仅在以下情况停下来：

- 用户需要给出人工正式结论；
- 动作属于 `AGENTS.md` 规定的待确认权限；
- 两种解释会导致不同岗位、候选人或正式状态变化；
- 缺少无法以“未验证”保留、且会让业务判断失真的关键事实；
- 外部信息尚未发生或尚未提供，继续分析不会增加信息。

如果 AI 仍能通过现有材料完成分析、比较或生成验证问题，先做完再向用户提出最小决定，不提前打断。

### 5. 保持连续上下文

- “前两个”“其余”“他们”只绑定到最近一次明确展示且顺序冻结的候选人集合；
- “按建议执行”“可以”“就这样”只确认上一条消息中清楚列出的决定映射；
- 用户同时给出例外时，先展开成逐人结果，再交给专业确认流程；
- 新岗位、新名单或明显切换话题后，不沿用旧指代；
- 指代存在两个同样合理的对象时，只问一个能解除歧义的问题，不猜测。

用户已经明确确认后，立即执行对应动作，不重复询问同一个决定。

### 6. 汇总判断变化和决策成熟度

有新材料或新结论时，优先说明：

- 原判断；
- 新增、削弱或冲突的证据；
- 当前判断；
- 为什么发生变化；
- 还可能改变判断的一个关键事实。

需要用户决定时，用定性状态说明：

- **证据已足够，可以决定**；
- **倾向明确，只需验证一个关键问题**；
- **当前不应下结论**。

不得把该状态转成分数、百分比或虚假置信度。

### 7. 用统一结果格式交付

对话默认按实际需要组合以下内容，不为没有内容的部分保留空标题：

1. **结果**：先用一至三句话说明完成了什么和当前结论；
2. **关键判断**：最多三项真正影响取舍的证据、差异或变化；
3. **只需你决定**：给出明确选项、AI 当前倾向和可直接复制的最小回复；
4. **接下来**：说明确认后将继续完成什么，或哪些工作已经直接完成；
5. **详细材料**：只列最关键的本地业务文件路径。

同一批任务有多个结果时，先按业务对象合并，不逐个复述内部步骤。没有需要用户决定的事项时直接说明已经完成，不制造确认。

## 对话底线

- 结果先于过程，业务语言先于系统语言；
- 用户不需要打开文件才能完成当前最小决定；
- 完整证据必须落盘，但对话只保留支持行动所需的信息；
- 一轮最多突出三个独立事项；其余说明可以稍后处理及重新进入条件；
- 不把“我可以继续”当作行动。授权范围内能继续的工作直接完成；
- 不用“请查看文件后反馈”把 AI 能完成的阅读和提炼退回用户；
- 不因追求连续执行而越过人工结论和正式画像的确认边界。
