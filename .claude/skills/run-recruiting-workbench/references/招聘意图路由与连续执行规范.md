# 招聘意图路由与连续执行规范

本文规定招聘工作台总入口如何把自然语言目标转换成最短完整的招聘行动链。它不替代专业 Skills 的判断规则，只决定读取什么、调用什么、何时连续执行、何时需要用户决定，以及最后如何以统一方式交付。

## 1. 总入口的产品目标

总入口应让用户获得以下体验：

- 只说招聘目标，不说系统步骤；
- 一次任务尽量一次完成；
- 不需要知道文件归属、Skill 名称和 CLI；
- AI 能完成的事情不会变成用户待办；
- 用户只看到结果、取舍和真正需要做出的决定；
- 回复一句自然语言后，流程可以从上一轮继续。

总入口不是菜单、聊天机器人欢迎页或新报告。它是工作台的默认理解与编排方式。

## 2. 总入口与专业 Skills 的关系

### 2.1 总入口负责

- 理解用户目标；
- 找到正确业务对象；
- 读取当前流程状态；
- 选择一个或多个专业 Skill；
- 决定执行顺序；
- 合并重复步骤；
- 维护连续对话中的名单和指代；
- 控制何时打断用户；
- 统一最终对话表达。

### 2.2 专业 Skills 负责

- 岗位画像和选人标准；
- 简历证据判断和四档建议；
- 候选人比较；
- 人工结论解析与落盘；
- 面试问题和纪要分析；
- 终面决策简报；
- 归档、历史复用和岗位校准；
- 个人偏好的识别与确认；
- 今日注意力优先级。

### 2.3 选择原则

- 目标明确且只有一个环节：直接使用专业 Skill；
- 目标模糊、跨环节、依赖上一轮或要求“直接处理”：使用总入口；
- 总入口选择专业 Skill 后，专业 Skill 的规则优先；
- 总入口不能用简化路由规则覆盖正式岗位或候选人证据。

## 3. 用户意图的六种形态

### 3.1 明确单环节

例如：

- “创建企业 AI 产品经理岗位。”
- “比较这个岗位的候选人。”
- “给王小明准备二面。”

直接路由到对应专业 Skill，不额外说明路由过程。

### 3.2 模糊但对象明确

例如：

- “看看王小明。”
- “这个岗位怎么办？”
- “这个人还值得继续吗？”

结合当前阶段推断最可能的业务问题。能在不改变正式状态的情况下先给现状和高价值判断时，先完成；只有存在两个会导致不同正式动作的解释时才提问。

### 3.3 跨环节任务

例如：

- “处理这批简历，告诉我先约谁。”
- “分析完一面以后，给我准备终面。”
- “归档这个人，以后有类似岗位还能找到。”

拆成内部行动链，一次完成所有无需用户确认的步骤。

### 3.4 连续指令

例如：

- “前两个推进。”
- “给他们准备一面。”
- “按刚才建议执行，王五除外。”

使用上一轮冻结的业务集合和决定映射。没有歧义时不要求用户重复姓名和岗位。

### 3.5 全局注意力

例如：

- “今天先做什么？”
- “我只有半小时。”
- “哪些岗位卡住了？”

使用今日招聘简报规则，结合用户时间、容量和真实期限压缩为少量行动。

### 3.6 反馈与纠正

例如：

- “你不该把参与项目当成主导。”
- “以后先给我排序，不要逐个人讲。”

先处理本案影响，再判断是否需要进入个人偏好学习；不得直接把纠正泛化成长期规则。

## 4. 最小状态读取

### 4.1 全局请求

读取：

- `04_全局索引/岗位清单.csv`；
- `04_全局索引/全部候选人.csv`；
- `04_全局索引/待确认事项.md`；
- 待处理目录；
- 必要时读取正式岗位和候选人主档案。

索引只用于定位，结论必须回到 Markdown 主档案。

### 4.2 岗位请求

读取：

- 正式 `岗位.md`；
- `候选人比较.md`；
- `本批次待人工确认.md`；
- 活跃候选人总览；
- 已确认个人偏好。

### 4.3 候选人请求

读取：

- `00_候选人总览.md`；
- 最新简历分析；
- 历轮面试报告；
- 面试准备或终面简报；
- 对应正式岗位；
- 需要比较时读取同岗位候选人。

### 4.4 连续请求

优先使用最近一轮对话中已经明确展示的：

- 名单；
- 顺序；
- 批次；
- AI 建议；
- 用户待决策项；
- 计划中的下一步。

不得仅靠陈旧索引猜测“前两个”指谁。

## 5. 单环节路由表

| 用户目标 | 首选 Skill | 典型触发 |
|---|---|---|
| 建立或澄清岗位 | `/create-position` | 新岗位、JD、岗位画像、选人标准 |
| 处理新简历 | `/process-resumes` | 新简历、筛选一批人、先约谁 |
| 横向比较 | `/compare-candidates` | 谁更强、只能选 N 人、A 为什么在 B 前 |
| 确认筛选结论 | `/confirm-screening` | 前两个推进、其余淘汰、修改某人结论 |
| 面试准备 | `/prepare-interview` | 下一轮问什么、重点验证什么 |
| 面试纪要分析 | `/analyze-interview` | 新纪要、第 N 轮、是否值得继续 |
| 终面简报 | `/generate-final-brief` | 终面、录用讨论、最后还缺什么 |
| 结束与归档 | `/close-candidate` | 录用、淘汰、退出、HC 暂停、归档 |
| 历史人才 | `/search-history` | 找以前的人、类似候选人、重新看看 |
| 岗位校准 | `/calibrate-position` | 招不到、反复误判、转化异常 |
| 首次校准或学习偏好 | `/learn-recruiting-preferences` | 先校准我的招聘偏好、先了解我怎么选人、记住这条、我不同意、以后这样判断 |
| 今日重点 | `/daily-recruiting-brief` | 今天先做什么、有什么卡点、只有半小时 |

路由表只决定入口，不代替对应 Skill 的完整触发和判断规则。

### 5.1 首次校准的非阻塞路由

- 用户明确请求校准：立即路由，每次只问一个情境问题。
- 正式偏好为 0 且用户正在做真实任务：先完成任务，再邀请一次；用户未接受时不重复提醒。
- 已有状态为“已暂停”的工作稿，用户说“继续”：从下一个未完成维度续接，不重问。
- 校准进行中用户切换到真实招聘任务：先暂停并保存进度，再执行新目标。
- 校准形成的规则候选在编号确认前只是工作稿，不得传递给简历、比较、面试或终面 Skill 作为有效偏好。

## 6. 多环节组合路径

### 6.1 新岗位到可筛选状态

用户目标：“根据这份 JD 和我讨论清楚，然后建岗。”

路径：

1. 使用 `/create-position` 澄清决定性标准；
2. 用户确认正式画像；
3. 创建岗位；
4. 扫描历史可复用人才；
5. 统一汇报已建岗位、关键取舍和历史命中。

没有确认画像前，不提前创建正式版本。

### 6.2 新简历到批量决定

用户目标：“处理新简历，告诉我先约谁。”

路径：

1. 使用 `/process-resumes` 完成识别、归档、证据分析和岗位内比较；
2. 合并为推进、待定、淘汰建议及相邻差异；
3. 停在人工结论写入前；
4. 给出可直接回复的批量决定；
5. 用户确认后使用 `/confirm-screening` 立即执行；
6. 若用户同时要求准备面试，再为已推进候选人使用 `/prepare-interview`。

用户在看到具体名单前说“按 AI 建议处理”，不能作为对未知映射的提前确认。

### 6.3 面试纪要到下一轮行动

用户目标：“分析一面，值得的话准备二面。”

路径：

1. 使用 `/analyze-interview` 处理纪要并判断本轮变化；
2. 人工正式面试结论尚未给出时，先呈现最小决定；
3. 用户确认继续后写入人工结论；
4. 使用 `/prepare-interview` 生成下一轮方案；
5. 对话只说明判断变化、是否值得继续和下一轮唯一核心目标。

不得把 AI 的“建议推进”自动写成人工“通过”。

### 6.4 终面到归档

用户目标：“给他做终面简报，结束后按我的结果归档。”

路径：

1. 使用 `/generate-final-brief`；
2. 等待用户提供最终人工结果；
3. 使用 `/close-candidate` 区分结束原因、能力判断和复用条件；
4. 重建历史索引；
5. 汇报最终结果和未来何时值得重新看。

### 6.5 招聘困难诊断

用户目标：“这个岗位一直招不到，看看问题在哪。”

路径：

1. 读取正式岗位画像、筛选建议、人工结论、面试和结束结果；
2. 使用 `/calibrate-position` 区分岗位定义、证据规则、面试验证和外部条件；
3. 必要时使用 `/search-history` 判断是否遗漏历史人才；
4. 只提出校准建议，不修改正式画像；
5. 告诉用户最可能的问题、最小验证动作和需要确认的修改。

## 7. 用户是否需要介入

### 7.1 直接执行

- 读取和整理材料；
- 生成 AI 分析；
- 同岗位比较；
- 生成面试准备、终面简报和校准建议；
- 重建索引和校验；
- 移动明确匹配的待处理文件；
- 创建候选人档案；
- 用户已明确确认后的受控执行。

### 7.2 必须停下

- 写入首次人工正式筛选或面试结论；
- 修改已有人工结论；
- 修改正式岗位画像；
- 修改已确认个人偏好或公司长期认知；
- 跨岗位移动候选人；
- 删除原始文件；
- 两个对象都合理且选择会改变正式归属；
- 缺少决定性业务事实，无法通过“未验证”安全保留。

### 7.3 可以带着不确定性继续

- 简历没有证明某项能力，但可标为未验证；
- 非关键 OCR 片段低置信度；
- 某个风险需要面试验证；
- 当前只能给“建议待定”且有明确补证条件；
- 对话表达不完整，但不影响材料归属或正式状态。

不要为了追求零不确定性频繁打断用户。

## 8. 连续对话与指代

### 8.1 冻结最近名单

当对话展示排序或批量建议时，内部保留：

- 岗位；
- 候选人完整名单；
- 展示顺序；
- 分组；
- 建议；
- 生成时间和来源文件。

在用户完成本次确认前，“前两个”“第三名”“其余”“他们”均基于该冻结集合。

### 8.2 确认短语

以下短语只有在上一条已经给出准确映射时才可执行：

- “按建议执行”；
- “可以”；
- “就这样”；
- “确认”；
- “前两个推进，其余淘汰”。

执行前内部展开为逐人决定。存在例外时先应用例外，再校验每个人只有一个结果。

### 8.3 话题切换

出现新岗位名、新候选人名、新文件或“另外一个岗位”等明显信号时，清除不再适用的旧指代。不得把旧批次的“他们”带入新岗位。

### 8.4 上下文不可靠

如果最近一次名单没有完整显示、顺序后来发生变化或对话中存在多个“前两个”，只问：

> 你说的“前两个”是刚才企业 AI 产品经理排序中的张三和李四吗？

不要要求用户重述整个任务。

## 9. 模糊请求的处理

### 9.1 “看看这个人”

默认先给：

- 当前岗位和流程阶段；
- 最新 AI 倾向与人工结论；
- 最近一次判断变化；
- 当前最值得解决的问题。

如果用户当前上下文明确是比较、面试或终面，则进入对应 Skill。不要先问宽泛的“你想看什么”。

### 9.2 “这个岗位怎么样”

默认回答：

- 当前最接近的业务决定；
- 最值得关注的候选人或批次；
- 主要阻塞；
- 下一步所有者。

只有用户要求完整盘点时才展开全部状态。

### 9.3 “处理一下”

如果用户刚提供文件或待处理区有新材料：

1. 识别材料类型；
2. 明确匹配的直接进入对应流程；
3. 不明确的形成一个可直接回答的问题；
4. 汇总全部处理结果。

若没有新材料且没有明确对象，说明当前没有可处理内容，并给出最近的真实触发点，不虚构任务。

### 9.4 “继续”

继续最近一个尚未完成、目标明确且没有新权限扩张的业务链。若最近任务已完成，说明完成结果和下一个高价值动作，不重复执行。

## 10. 统一对话结果

### 10.1 默认短格式

```text
结果
这批 6 份简历已经处理并完成岗位内比较。
建议先约张三和李四，王五待定，其余不建议继续。

关键判断
- 张三排第一：……
- 李四与张三的决定性差异：……
- 王五暂不淘汰：……

只需你决定
是否确认张三、李四推进，王五待定，其余淘汰？
你可以回复：“按建议执行”，或只说需要调整的人。

确认后
我会写入人工结论，并为推进的两人准备下一轮面试。
```

### 10.2 不需要决定

```text
王小明的二面准备已经生成。

本轮只验证一个核心问题：他是否真正做过关键产品取舍，而不只是协调项目推进。
时间不足时优先问前三题，详细追问和强弱信号已保存到面试准备文件。
```

### 10.3 当前不能决定

```text
当前不应该决定是否推进。

原因不是候选人已明确不符合，而是原始 PDF 有两页正文无法完整识别，恰好涉及最近一段经历。

只需你确认：
这份文件是否有更清晰版本？如果没有，我会基于可读内容继续，但把相关经历保持为未验证。
```

### 10.4 表达约束

- 先说业务结果，不以“已扫描”“已调用”“已生成索引”开头；
- 最多三条关键判断；
- 决策问题必须可以用一句话回答；
- 需要展示路径时，只列用户可能打开的业务文件；
- 不列日志、缓存、内部命令和所有读取文件。

## 11. 决策成熟度

### 11.1 证据已足够，可以决定

适用：

- 岗位标准清楚；
- 关键事实已有足够证据；
- 主要风险已知；
- 继续补证的边际价值低；
- 用户面临明确取舍。

仍需保留最大风险和反转条件。

### 11.2 倾向明确，只需验证一个关键问题

适用：

- 当前方向已经形成；
- 仍有一个问题可能改变排序或推进结论；
- 该问题可以低成本在下一轮验证。

必须说出具体问题、强弱证据和可能变化，不能只写“建议进一步了解”。

### 11.3 当前不应下结论

适用：

- 材料无法完整读取；
- 岗位归属不清；
- 正式岗位标准尚未确认；
- 关键事实相互冲突；
- 当前信息只足以描述、不能支持取舍。

应说明缺少什么和最小补充动作，不把信息不足写成候选人不足。

## 12. 批量决定体验

### 12.1 先给分组，再给边界

用户首先需要看到：

- 建议推进；
- 建议待定；
- 建议淘汰；
- 最难取舍的一组；
- 最后一名入选者与第一名未入选者的差异。

不需要逐份阅读完整摘要后自行重组。

### 12.2 提供最小回复

推荐：

> 回复“按建议执行”，或直接说“王五改成推进”。

不推荐：

> 请逐一确认以上六名候选人的处理意见。

### 12.3 执行后继续

人工确认写入后：

- 说明完成了哪些正式决定；
- 若用户已要求准备面试，直接继续；
- 若没有后续授权，只给一个最有价值的下一步；
- 不再次要求用户确认刚确认的名单。

## 13. 待确认与异常体验

### 13.1 人名或岗位不清

不要只报待确认文件路径。给出最可能选项及依据：

> 姓名识别为王小明，但岗位不能唯一确定。最可能是企业 AI 产品经理或 AI 解决方案负责人。回复岗位名称即可继续。

如果没有可靠候选项，直接请用户提供岗位，不猜测。

### 13.2 面试轮次不清

结合已有轮次列出可选项：

> 王小明已经有一面记录，这份纪要最可能是二面。回复“二面”即可继续；如果是其他轮次，直接告诉我轮次。

### 13.3 OCR 或文本不完整

说明：

- 哪部分无法读取；
- 是否影响当前判断；
- 能否基于现有内容安全继续；
- 用户最小补充动作。

不得只说“识别失败”。

### 13.4 新材料可能改变已确认结论

先完成新旧差异分析，但不修改正式结论：

> 新版简历增加了直接相关经历，AI 建议可能从待定调整为推；你此前的人工结论仍保持待定。是否确认根据新版材料重新审视？

### 13.5 无事可做

明确说当前没有需要处理的招聘事项，并说明下一个真实触发点。不要为了展示总控能力创建虚假优先级。

## 14. 主动下一步的边界

### 14.1 可以直接继续

如果下一步：

- 已包含在用户原始目标中；
- 不需要新增权限；
- 不改变人工正式结论；
- 使用现有材料即可完成；

则直接执行。

例如用户说“处理简历并告诉我先约谁”，应完成比较，不在完成建档后停下来问是否继续分析。

### 14.2 只建议，不自动执行

如果下一步：

- 是新的业务方向；
- 会改变正式状态；
- 需要用户投入时间；
- 需要新的外部协调；

只给一个最有价值建议，并说明原因。

### 14.3 不给下一步菜单

不要列出五个“还可以帮你做”的能力。只提出一个与当前证据最相关的动作；没有高价值动作时不提。

## 15. 典型使用场景

### 场景一：空工作区

用户：“我要招一个企业 AI 产品经理。”

行为：

- 进入 `/create-position`；
- 先讨论真正改变准入和排序的问题；
- 不要求用户先填写目录或模板；
- 确认后建岗并扫描历史人才。

### 场景二：混合新材料

用户：“处理一下刚放进来的材料。”

行为：

- 简历进入 `/process-resumes`；
- 面试纪要进入 `/analyze-interview`；
- JD 进入 `/create-position` 讨论；
- 无法识别的材料给出一个最小确认问题；
- 最终按岗位和决定合并汇报。

### 场景三：批量确认

用户：“按建议执行，王五改成推进。”

行为：

- 基于上一轮冻结名单展开逐人映射；
- 使用 `/confirm-screening`；
- 保留 AI 原建议和用户例外；
- 执行后说明正式结论已写入。

### 场景四：连续面试准备

用户：“给前两个准备一面。”

行为：

- 确认“前两个”来自最近冻结排序；
- 分别使用 `/prepare-interview`；
- 对话合并说明两人的不同验证重点；
- 不把两份完整问题清单全部贴入对话。

### 场景五：候选人值不值得继续

用户：“王小明还有必要继续面吗？”

行为：

- 读取岗位、总览、简历和历轮报告；
- 使用 `/analyze-interview` 的累积证据和下一轮价值规则；
- 给出明确倾向、剩余决定性问题和再面一轮的信息价值；
- 人工结论未给出时不自动写入。

### 场景六：时间有限

用户：“今天只有二十分钟。”

行为：

- 使用 `/daily-recruiting-brief`；
- 把事项压缩到一个可完成的决定；
- AI 可完成的准备工作直接做；
- 明确哪些事情今天不处理不会造成损失。

### 场景七：用户纠正判断

用户：“李四虽然不是最终负责人，但他负责的范围里做了关键取舍，不能因此说他只是执行。”

行为：

- 先修正本案证据解释；
- 使用 `/learn-recruiting-preferences` 判断是否只属个案；
- 如形成偏好候选，展示范围、规则和例外；
- 未确认前不影响其他候选人。

### 场景八：岗位长期招不到

用户：“这个岗位一直招不到，别再给我堆简历了，看看问题在哪。”

行为：

- 使用 `/calibrate-position`；
- 区分画像、证据规则、面试验证和外部条件；
- 必要时用 `/search-history` 检查历史人才；
- 给一个最值得验证的校准建议，不直接修改正式画像。

## 16. 常见错误

- 把总入口写成 Skill 菜单；
- 一开始就解释将调用哪些 Skills；
- 每完成一步就询问“是否继续”；
- 用户说“处理简历”后只完成文件归档，没有完成业务判断；
- 把 AI 可完成的比较和提炼退回用户；
- 用户已经确认后再次重复确认；
- 使用旧名单解释新的“前两个”；
- 为保持连续而跨过人工正式结论边界；
- 用总控简短规则替代专业 Skill 的完整证据标准；
- 输出所有文件路径和内部命令；
- 没有重要事项时仍凑满三项；
- 给出多个泛化下一步，让用户重新选择工作流。

## 17. 执行前后自检

### 执行前

- [ ] 我理解的是用户要获得的业务结果，而不是字面命令；
- [ ] 已确定正确的岗位、候选人、批次或全局范围；
- [ ] 只读取了支持本次任务的必要状态；
- [ ] 已选择最短完整专业 Skill 路径；
- [ ] 没有重复专业流程已经包含的步骤；
- [ ] 连续指代绑定到最近明确且冻结的集合；
- [ ] 需要用户确认的边界已识别。

### 执行后

- [ ] 已完成所有无需用户介入且在原目标内的步骤；
- [ ] 专业判断来自对应 Skill 和正式主档案；
- [ ] 原始事实、AI 建议和人工结论保持分层；
- [ ] 对话先给结果，没有先讲系统过程；
- [ ] 关键判断不超过三项；
- [ ] 用户能不打开文件完成当前最小决定；
- [ ] 有新证据时说明了判断变化；
- [ ] 待确认或异常已转换成可直接回答的问题；
- [ ] 没有制造虚假紧迫感或无意义下一步；
- [ ] 重要产物已落盘并通过相关校验。
