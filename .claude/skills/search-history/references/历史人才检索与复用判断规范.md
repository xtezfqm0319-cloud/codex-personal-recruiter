# 历史人才检索与复用判断规范

## 1. 查询要解决的业务问题

搜索前先把用户问题改写成一句决策任务，例如：

- “为当前企业产品负责人岗位找三名最值得重看的历史候选人”；
- “查清王某上次为什么没有继续，以及现在是否值得联系”；
- “找已有复杂交付证据、但此前因 HC 结束的人”；
- “回顾过去在商业化能力上误判过的候选人”。

没有明确决策任务时，关键词越多不代表结果越准。

## 2. 五类查询意图

### 2.1 指定人历史回顾

身份命中优先，完整说明原岗位、流程阶段、证据、人工结论、结束原因和当前资料时效。

### 2.2 当前岗位人才复用

必须以当前正式岗位画像重判，不沿用原岗位建议。

### 2.3 能力或任务检索

关键词只负责召回，最终判断要看候选人是否有对应行为证据与个人贡献。

### 2.4 结果或结束原因检索

例如“因 HC 暂停”“通过业务面但未入职”。必须读取最终结果与归档摘要，不从文件名猜测。

### 2.5 批次或模式回顾

可以回答共同模式，但不能把多个不同岗位、不同画像版本的人强行放在同一排名中。

## 3. 什么时候需要追问

只有以下信息缺失且会明显改变结果时追问：

- 当前要服务的岗位完全不明确；
- “找最好的人”没有说明最好是指什么任务；
- 同名候选人无法唯一识别；
- 用户要求立即跨岗位启用，但目标岗位不明确。

其他时候先用现有上下文搜索，并把未给条件写为查询边界。

## 4. 从自然语言提取召回维度

把需求拆成：

- 候选人或原岗位身份；
- 当前岗位核心任务；
- 关键能力或行为证据；
- 行业、客户、业务阶段或产品场景；
- 流程阶段、最终结果和结束原因；
- 用户明确要求的限制条件。

选择两到五组辨识度高的查询词分别召回。不要把整句自然语言作为唯一关键词，也不要只搜索岗位名称。

## 5. 召回词的选择

优先选择主档案中可能实际出现的业务词：任务、项目、产品、客户、决策、结果、结束原因。避免单独使用“优秀”“能力强”“合适”等抽象词。

同义表达应分别考虑，例如：

- 企业服务 / B 端 / ToB；
- 商业化 / 收入 / 付费 / 定价；
- 0 到 1 / 从无到有 / 新产品；
- HC 暂停 / 编制暂停 / 岗位取消。

## 6. 召回不等于匹配

关键词命中只能证明文本包含某个词。常见假命中包括：

- 风险段写“缺少商业化”，却因“商业化”被召回；
- 面试问题问过某能力，但候选人没有回答；
- 原岗位要求包含关键词，候选人材料并无对应证据；
- AI 摘要多次复述同一主张；
- 结束原因提到某岗位，但候选人并不适配该岗位。

因此每个候选人必须回到上下文确认命中位置和语义方向。

## 7. 当前岗位决策模型

存在当前岗位时，提取：

- 一票否决条件；
- 能力底线；
- 决定性排序因素；
- 关键经历和证据标准；
- 取舍与经历替代规则；
- 可放宽条件；
- 面试重点验证。

历史人才重判应逐项映射这些规则。原岗位与当前岗位同名，也不能假设画像版本和业务重点相同。

## 8. 候选人历史证据包

每名候选人的最小读取集合：

1. `归档摘要.md`；
2. `00_候选人总览.md`；
3. `01_简历分析.md`；
4. 最关键的一至两轮面试报告；
5. 最终人工结论和结束原因；
6. 原岗位画像。

归档摘要缺失的旧数据应从主档案重建理解，但不要自动改写旧档案，除非用户要求补档。

## 9. 证据分级与去重

按以下顺序理解证据：

1. 可核验结果、具体决策、行为细节和反例；
2. 多轮材料中新增且相互独立的具体信息；
3. 候选人单方主张；
4. 面试官或 AI 的概括评价；
5. 关键词命中。

同一经历在简历、总览、面试和终面简报中重复出现，仍是一组来源链，不是四份独立证据。

## 10. 旧结论的有效范围

历史结论必须携带原岗位、当时画像、阶段和证据边界：

- 原岗位“强推”只说明当时简历阶段的相对判断；
- 原岗位“淘汰”不等于当前岗位也应淘汰；
- 某轮面试“通过”不代表所有能力已验证；
- “不建议复用”应尊重原证据，但指定人回顾时仍需解释原因；
- “优先复用”也不等于当前意愿、薪资、地点和近况仍有效。

## 11. 原流程结束原因的影响

### 外部条件原因

HC、预算、业务变化、地点、时机、Offer 条件等通常不削弱能力证据，但可能影响当前可行性。

### 岗位匹配原因

要识别当前岗位是否恰好不同。如果当前岗位仍要求同一被反证能力，则不应复用；如果职责边界变化，则可重新判断。

### 能力或可信度原因

必须引用具体判断项和证据，不泛化到全部能力。严重可信度风险未解决时，不因新岗位不同而忽略。

### 信息不足

说明重新评估成本和最小验证动作，不能假装已有结论。

## 12. 资料时效

所有历史档案都是过去某一时间点的记录。默认将以下内容标记为当前未验证：

- 求职意愿；
- 当前公司与职责；
- 薪资和地点条件；
- 最近项目和能力变化；
- 可以入职的时间；
- 旧风险是否已经改善。

资料旧不等于候选人不合适，但会增加重新判断的不确定性。

## 13. 四类当前复用优先级

### 13.1 值得优先重看

当前岗位决定性任务已有较强历史证据；原结束原因不否定该价值；主要缺口可以低成本更新。

### 13.2 值得重新评估

存在明确价值，但当前岗位与原岗位有关键差异，或需要一轮有针对性的重新验证。

### 13.3 补一项关键信息后再看

一个外部条件、时效信息或单一证据缺口决定是否值得投入；先获取这项信息比直接安排面试更有效。

### 13.4 当前不建议复用

当前岗位的核心要求与已有反证直接冲突，或重新验证成本明显高于潜在价值。必须说明“当前”和“针对什么需求”，不做永久人格判断。

## 14. 多人比较与排序

比较时统一使用当前岗位标准，并区分：

- 岗位适配；
- 历史证据成熟度；
- 当前重新投入价值；
- 需要更新的信息成本。

排序必须解释相邻候选人的决定性差异。证据相当时允许并列，并说明打破并列的最小信息。不得因原流程更深就自动排在前面。

## 15. 每名候选人的输出单元

```markdown
### 候选人｜当前复用优先级

- 为什么现在值得看：
- 最强历史证据：
- 最强反证或边界：
- 原流程结束原因：
- 原岗位与当前需求的关键差异：
- 已经过时或当前未验证的信息：
- 最小下一步：
- 什么新证据会提高或降低优先级：
- 证据路径：
```

## 16. 正式岗位复用建议格式

```markdown
# 当前岗位｜历史人才复用建议

## 一、本次查询与边界
## 二、优先结论
## 三、候选人逐人判断
## 四、岗位内相对顺序与取舍
## 五、当前没有足够证据的人
## 六、最小下一步
## 七、输入材料与追溯
```

此文件是当前岗位业务视图，不复制历史候选人档案，也不改变其归属。

## 17. 未命中的正确表达

不要说“人才库里没有”。应区分：

- 没有任何关键词召回；
- 有召回但没有当前岗位证据；
- 有潜在线索但档案信息不足；
- 有能力证据但当前条件不适合；
- 现有历史数据覆盖有限。

推荐表达：“现有已归档材料中，没有找到足以支持当前需求的候选人；有两名关键词命中，但命中来自岗位要求或风险段，不能作为匹配证据。”

## 18. 只读和权限边界

检索可直接读取、比较、生成建议和写业务视图。不得：

- 把历史候选人自动移动到当前岗位；
- 复制档案制造两个主档案；
- 修改历史人工结论；
- 把新的当前岗位判断写回原岗位事实；
- 因一次查询改公司级长期认知。

用户明确决定重新启用后，跨岗位动作仍需待确认。

## 19. 写入前自检

1. 是否明确本次查询要支持的决定；
2. 是否读取当前岗位正式画像；
3. 是否使用多组有辨识度的召回词；
4. 是否把关键词命中仅作为召回；
5. 是否回到 Markdown 主档案；
6. 是否读取原流程结束原因；
7. 是否区分历史能力证据与当前可行性；
8. 是否对重复材料去重；
9. 是否说明资料时效；
10. 是否按当前岗位而非原岗位重判；
11. 是否保留旧人工结论而不改写；
12. 是否给出最强反证或边界；
13. 是否给出最小下一步；
14. 多人顺序是否解释相邻差异；
15. 证据不足时是否允许并列；
16. 是否没有使用精确评分；
17. 是否没有自动移动或加入候选人；
18. 未命中时是否避免过度断言；
19. 关键判断是否引用本地路径；
20. 回复是否先回答“谁值得重看、为什么”。
