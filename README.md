# Codex / Claude Code 个人招聘工作台

**你负责找人和做决定，整理文件、归档材料、筛选比较和准备报告这些重复工作，交给 Codex 或 Claude Code。**

这是一个可以直接在 Codex 或 Claude Code 中使用的本地个人招聘工作台。它会陪你完成从建岗位、筛简历、排候选人、准备面试，到终面决策和人才归档的完整流程。它不只是把简历总结一遍，而是真的替你整理材料、维护岗位进展，并逐渐记住你真正看重什么。

这个项目适合独立负责招聘的 HR、招聘负责人、HRBP，以及需要深度参与选人的业务负责人。它不是一套需要部署和维护的 ATS，也不是面向所有公司的通用 SaaS；你可以把它 fork 下来，慢慢调成只服务你和你公司的个人招聘工作台。

> [!IMPORTANT]
> **使用订阅登录时，不用接模型 API，也没有单独的 API 账单。** Codex 可使用包含它的 ChatGPT 套餐；Claude Code 可使用 Claude Pro、Max、Team 或 Enterprise 等支持的订阅。项目本身不调用外部模型 API，也不需要服务器、数据库或另一套招聘系统。使用 API Key 登录则可能按供应商规则计费，具体以 [Codex 官方说明](https://learn.chatgpt.com/docs/pricing) 和 [Claude Code 官方说明](https://code.claude.com/docs/en/authentication) 为准。

## 最新更新：你只说目标，工作台自己把流程跑起来

当前版本为正式版 `v1.0.0`。它已经形成从自然语言总入口到岗位、候选人、面试、终面、归档和历史复用的完整个人招聘闭环，不增加网页、服务或外部模型 API：

- 用户不再需要判断该调用哪个 Skill，可以直接说“处理一下新材料”“这个岗位现在怎么样”“王小明还有必要继续吗”；
- 总入口会读取当前工作区，选择并组合已有专业流程，一次完成所有不需要用户介入的步骤；
- “前两个推进”“给他们准备一面”“按刚才建议执行，王五除外”等连续表达可以沿用最近一次明确名单，不要求重新输入姓名和岗位；
- 简历处理、岗位内比较、批量确认和面试准备可以形成连续任务，不在每个内部环节停下来询问是否继续；
- 对话统一先给业务结果和关键取舍，再给一个可直接回答的最小决定；完整证据继续保存在本地文件；
- 待确认和识别异常会转换成可直接回答的问题，不只告诉用户去找某个文件；
- 现有 12 个专业招聘 Skills 保持原有准确性规则，总入口只负责编排，不用简化规则替代专业判断。

完整版本记录见 [`CHANGELOG.md`](CHANGELOG.md)。

## 最直观的例子：处理一批刚下载的简历

以前，你可能需要逐个打开简历、判断属于哪个岗位、改文件名、寻找岗位文件夹、建立候选人目录、填写表格，再把几个人放在一起比较。

现在，你只需要：

1. 把下载的简历统一放进 `01_待处理/简历/`，不需要先寻找每个岗位对应的文件夹。
2. 对当前 AI 助手说：“处理新简历，告诉我这批人应该先约谁。”
3. AI 助手会读取岗位要求并完成分析；本地脚本负责识别、重命名、移动、建档、更新索引和校验。

处理完成后，它会自动：

- 读取 PDF、Word、TXT，以及图片版或扫描版 PDF；
- 识别候选人姓名和目标岗位；
- 把简历统一重命名为“姓名-岗位”；
- 移入对应岗位和候选人的文件夹，并保留原始简历；
- 在岗位目录下生成候选人总览、简历分析和批量确认清单；
- 按同一个岗位横向比较所有候选人，告诉你谁更值得先见、为什么；
- 对无法确认的人名、岗位或文本内容明确提出问题，不擅自猜测。

也就是说，你打开一个岗位文件夹时，看到的不再是一堆散乱简历，而是已经整理好的候选人档案、判断依据、风险、排序和下一步建议。

面试纪要也是同样的用法：全部放进统一入口，AI 助手会识别候选人、岗位和轮次，归入对应候选人档案，生成面试报告并更新流程状态。候选人流程结束后，完整档案会进入历史人才库，以后新开相似岗位时还能重新找到。

## 它替你做掉哪些重复工作

| 过去经常手动做 | 现在交给工作台 |
|---|---|
| 反复寻找岗位和候选人文件夹 | 从统一待处理入口自动识别并归档 |
| 手工修改简历、纪要文件名 | 按姓名、岗位和轮次统一命名 |
| 在表格里复制候选人信息和流程状态 | 从候选人主档案自动重建岗位总表和索引 |
| 每看一份简历都重新回忆岗位要求 | 自动读取正式岗位画像后再分析 |
| 一个人一份摘要，最后仍要自己重新比较 | 直接给同岗位相对排序和关键取舍 |
| 面试前重新翻简历和上一轮纪要 | 自动整理最值得验证的问题、追问和强弱信号 |
| 终面前临时拼接所有材料 | 自动汇总证据、风险、未验证项和推进倾向 |
| 流程结束后材料散落、以后找不到 | 完整归档并进入可搜索的历史人才库 |
| 每天逐个岗位翻进展、自己想先做什么 | 跨岗位生成少量高价值事项和最小决策集 |
| 每次纠正 AI 后，下次还要重新解释 | 把明确反馈整理成带范围和例外的偏好，经确认后复用 |

## 它能给招聘判断什么帮助

| 招聘场景 | 它会怎么帮你 | 你最终得到什么 |
|---|---|---|
| 新开岗位 | 和你讨论 JD，追问真正影响选人的问题，适度质疑矛盾要求 | 可执行的岗位画像和筛选重点 |
| 一批简历进来 | 读取 PDF、Word、TXT 和扫描件，提取证据、风险并横向比较 | 四档建议、候选人排序和批量确认清单 |
| 准备下一轮面试 | 找出这个人最值得验证的能力、矛盾和证据缺口 | 针对性问题、追问方式和强弱信号 |
| 面试结束 | 区分面试官原话、AI 分析和你的正式结论 | 可追溯的独立面试报告和流程状态 |
| 终面或录用讨论 | 汇总岗位、简历、历轮面试和 HR 信息 | 有明确倾向、有证据、有未验证项的终面简报 |
| 候选人流程结束 | 保留完整经历、结果和未来复用价值 | 可搜索、可复用的本地人才档案 |
| 你纠正一次判断 | 区分个案、岗位规则和长期偏好，检查反例后请你确认 | 不会过度泛化的个人判断规则 |
| 查看今天重点 | 跨岗位区分用户决定、AI 动作和外部等待 | 最值得现在处理的少数事项 |

## 它和普通“AI 读简历”有什么不同

- **不是逐份摘要，而是帮你做取舍。** 它会告诉你谁更值得先见、为什么 A 排在 B 前面，以及面试名额有限时该如何选择。
- **不是每次重新开始，而是持续理解上下文。** 岗位画像、候选人材料、面试证据和流程状态都会沉淀在本地文件中。
- **不是替你武断做决定，而是把判断说清楚。** 事实、判断、风险和未验证项分开呈现，重要结论都能回到原始材料。
- **不是固定的一套招聘标准，而是会逐渐适应你。** 你解释为什么赞同或反对一次建议后，它会把可能的规律整理出来，经你确认后用于未来判断。
- **不用学一套新系统。** Codex 或 Claude Code 对话就是入口，你说目标，它负责读取材料、调用对应 Skill 并把正式结果落盘。

## 怎么用

不需要记命令，也不需要关心文件怎么移动。直接在 Codex 或 Claude Code 里说你想解决的问题即可，例如：

- “处理一下我刚放进来的材料，需要我决定时再找我。”
- “看看企业 AI 产品经理现在什么情况，直接告诉我下一步。”
- “今天招聘上我最应该先处理什么？”
- “这批候选人怎么排？如果只能约三个人，约谁？”
- “给王小明准备二面，别问已经确认过的事情。”
- “我不同意你推荐李雷，因为他只是参与者，不是真正负责人。先把这条整理成我的偏好候选。”
- “基于全部材料，明确告诉我王小明值不值得进入录用讨论。”

AI 助手会优先给结论、候选人之间的相对差异和下一步动作。文件整理、索引重建等例行操作只在失败或你主动询问时说明。

面对模糊、跨环节或依赖上一轮上下文的请求，工作台默认由 `run-recruiting-workbench` 总入口接住；如果你明确说“生成终面简报”或“比较这三名候选人”，也可以直接进入对应专业 Skill。总入口不会要求你选择菜单。

个人偏好保存在 `00_公司认知/个人招聘判断偏好.md`。只有你明确确认的规则才会影响正式判断；单个候选人的一次取舍不会被擅自泛化。

公开模板不预设任何通用淘汰门槛。需要执行的公司或岗位硬性条件，由你在本地 `00_公司认知/通用招聘标准.md` 或正式 `岗位.md` 中明确配置；信息缺失、明确不符合和经确认例外会分别记录。

完整流程可以很简单：

1. 在 Codex 或 Claude Code 中打开这个项目，根据自己的公司填写 `00_公司认知/`。
2. 给它一份 JD，说“先和我讨论清楚，再创建岗位”。
3. 把简历或面试纪要放进 `01_待处理/`，直接说“处理新材料”。
4. 用自然语言确认推进、待定或淘汰；后续面试、终面和归档继续在同一个项目里完成。

## 选择 Codex 或 Claude Code

两端共享相同的 Python CLI、Markdown 主档案、权限规则和招聘判断流程。可以任选其一，也可以在同一个本地项目中交替使用。

### 在 Codex 中

直接用 Codex 打开项目。Codex 会读取 `AGENTS.md` 和 `.agents/skills/`。自然语言会自动匹配 Skill，也可以用 `$process-resumes` 等名称显式调用。

### 在 Claude Code 中

在项目根目录启动：

```bash
claude
```

Claude Code 会通过 `CLAUDE.md` 导入共同规则，并自动发现 `.claude/skills/`。自然语言会自动匹配 Skill，也可以用 `/run-recruiting-workbench`、`/process-resumes`、`/prepare-interview` 等斜杠命令显式调用。进入后可运行 `/memory` 和 `/skills` 确认总入口与 12 个专业招聘 Skills 已加载。

项目维护者修改 `.agents/skills/` 后，应运行：

```bash
python scripts/sync_agent_skills.py --root .
python scripts/sync_agent_skills.py --root . --check
```

## 环境

- Python 3.11+
- 无网页、后端、数据库或外部模型 API
- 支持读取 TXT、Markdown、PDF、DOCX 简历/纪要
- PDF 支持本地 OCR 与逐页文本完整度检测；不上传文件、不调用外部模型 API

建议创建虚拟环境后安装：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

## 图片版 PDF 与本地 OCR

- 默认使用随 Python 依赖安装的 RapidOCR 本地 ONNX 模型，支持中英文，可直接在本地受限环境中运行。
- macOS 会在 RapidOCR 不可用时回退到系统 Apple Vision；其他环境还可回退到 Tesseract。Tesseract 处理中文时建议安装 `chi_sim` 语言包。
- 可用 `RECRUITER_OCR_BACKEND=rapidocr`、`vision` 或 `tesseract` 固定后端；设置为 `disabled` 可关闭 OCR。
- 程序逐页检查有效字符、异常字符和疑似视觉内容。低文本页会先 OCR；仍不完整或本地 OCR 不可用时，原文件和逐页质量报告会一起进入 `01_待处理/待确认/`，不会继续自动建档。
- 成功建档后，候选人目录保存 `原始简历提取质量.md`；面试轮次目录保存 `原始纪要提取质量.md`。报告中的“完整页”仅是技术覆盖指标，不是候选人评分。

若不安装项目，也可：

```bash
PYTHONPATH=06_系统 python -m recruiter --root . validate
```

## 第一次使用

1. 阅读并按实际公司情况填写 `00_公司认知/`。修改长期认知属于需确认动作。
2. 在 Codex 或 Claude Code 中说“根据这个 JD 和我讨论并新建岗位”。AI 助手会使用 `create-position` Skill。
3. 把简历放入 `01_待处理/简历/`，说“处理新简历”。文本 PDF、图片版 PDF 和扫描版 PDF 均可处理。
4. 查看岗位下的 `本批次待人工确认.md`，用自然语言批量给出结论。
5. 把面试纪要放入 `01_待处理/面试纪要/`，说“分析新面试纪要”。
6. 终面前说“给某某生成终面简报”；结束后说“归档某某，结果为……”。

## 数据安全

真实简历、纪要和候选人目录已通过 `.gitignore` 默认排除。仍应使用磁盘加密和可靠备份，并在处理真实数据前检查所用 AI 助手的账户与数据控制设置。不要把真实数据提交到公开仓库。

## 已知限制

- 项目未提供独立的既有终面简报 Prompt；当前以 `.agents/skills/generate-final-brief/references/终面简报规则.md` 为唯一维护源，并同步给 Claude Code，可由真实 Prompt 替换。
- OCR 识别质量受扫描清晰度、字体、排版和语言影响；低质量、手写、复杂双栏或无法完整识别的页面会进入待确认，不会被静默当作完整文本。
- 姓名和岗位匹配基于明确字段、文件名和岗位名称；模糊或冲突输入进入待确认，不猜测。
- Python 不做开放式语义招聘判断；需要由 Codex 或 Claude Code 按 Skill 分析，再用 `record-*` 落盘。
- 自然语言历史查询由当前 AI 助手读取索引和主档案完成；CLI 仅提供关键词只读检索。
- 个人招聘偏好不会从沉默或单次决定中自动猜测；首次使用时需要你通过实际反馈逐步确认。
- 今日简报、候选人比较和面试准备是可重建的辅助视图，准确度取决于主档案中已有材料、真实日期和流程状态的完整度。
- 旧版已经记录的自然语言偏好不会被自动重写成新结构；需要在后续实际使用或复核时逐条确认，避免系统替你改变原意。
